# i18n

## Model

- `src/i18n/ui.ts` — `languages` (URL prefixes), `htmlLang` (`<html lang>`
  values, BCP 47), `defaultLang = "es"`, and the `ui` string table keyed by
  locale. `UIKey` is derived from the `es` table, so every locale must define
  the same keys.
- `src/i18n/utils.ts` — `getLang(url)` (first path segment, defaults to `es`),
  `useTranslations(lang)` with `es` fallback, `getLocalePath(lang)` for home
  links, `getDocPath(lang, slug)` for doc links.

## Key naming

`section.element[.variant]` — e.g. `hero.title1`, `plan.pro.f1`,
`footer.company.privacy`, `notfound.back`, `seo.description`.

## Adding a language

1. Add the locale to `languages` and `htmlLang` in `ui.ts`.
2. Copy the full key set from `es` and translate every value.
3. Add `src/content/<lang>/` translations (see `content.md`); until then, doc
   routes fall back to `es`.
4. Rebuild — home, hreflang, sitemap, and the 404 page pick it up automatically.

## Translating content pages

Doc bodies live in `src/content/<lang>/*.md`, translated by hand to keep the
legal tone. Frontmatter (`title`, `description`, `eyebrow`) is translated too.
